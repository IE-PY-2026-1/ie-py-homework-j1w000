먼저 새로운 아이템을 영입할 때마다 아이템의 이름과 브랜드, 카테고리는 무엇인지, 그리고 가장 중요한 구매 가격과 내가 느끼는 체감 만족도 점수는 어느 정도인지를 상세하게 물어보고 기록하는 것으로 룩북의 첫 페이지를 넘깁니다. 그다음에는 입력받은 숫자 데이터를 바탕으로 이 아이템이 얼마나 가치 있는 소비였는지 판별하기 위해, 가격 대비 만족도를 계산하는 가성비 정밀 진단을 실시합니다. 만족도가 높고 합리적인 가격의 아이템에는 인생 역대급 아이템이라는 S등급의 영광을 부여하고, 가격에 비해 만족도가 낮은 아이템에는 신중한 소비가 필요하다는 의미의 D등급이라는 냉철한 판정을 내려 사용자에게 스마트한 쇼핑 가이드를 제공합니다.

특히 만족도가 만점이면서 코디의 핵심인 필수 기본템으로 분류된 아이템이 있다면, 진정한 시티보이의 완성이라는 특별한 칭호와 함께 별도의 관리 목록에 등록하는 깜짝 선물 같은 기능도 포함될 예정입니다. 나중에는 한두 개의 아이템만 기록하는 게 아니라, 내 옷장 속의 수많은 아이템을 커다란 주머니인 리스트에 한꺼번에 담아서 관리하고 언제든 명부를 꺼내 볼 수 있게 만들 것입니다.

마지막으로 이 모든 기능은 사용자가 메뉴판에서 번호를 눌러 아이템 등록, 조회, 분석 등을 자유롭게 선택할 수 있으며, 업무 종료를 선택하기 전까지는 계속해서 새로운 패션 아이템을 맞이하고 나만의 스타일을 연구할 수 있는 종합 패션 관리 소프트웨어로 완성될 계획입니다.

## 🟩 [2차 과제: V1.0] 입출력 + 리스트 + 조건문 - 향후 작성 예정
### **✨2차 과제 내용:**
2차 과제 내용:
이번 과제는 파이썬 기초 문법을 활용해 '캠퍼스 시티보이 룩북 및 코디 관리 프로그램'을 만들어보는 것입니다. 사용자에게 패션 아이템의 정보를 입력받아 리스트에 저장하고, 배운 연산자들을 활용해 나만의 '트렌드 지수'를 계산하는 시스템을 기획했습니다.
수업 시간에 배운 if-elif 조건문과 리스트 내장 함수들을 적극적으로 활용하여, 옷장 데이터를 수정하고 상황에 맞는 코디 등급을 판정하는 코드를 작성했습니다.

1.input() 함수로 아이템명(예: 아식스 젤-1130), 가격, 만족도(0~100)를 입력받아 리스트에 저장.

5.리스트 함수(pop, insert, index)를 활용해 만족도가 낮은 낡은 옷을 리스트에서 지우고, 새 아이템을 원하는 위치에 추가하는 기능 구현.

### **🛠️ Troubleshooting & 기술 회고:**
1. **문제 1: 숫자를 입력했는데 계산이 안 되는 현상 (TypeError)**
    * **원인:**input()으로 입력받은 옷 가격과 만족도는 파이썬이 기본적으로 '글자'로 인식해서, 그대로 제곱이나 나누기 연산을 하려고 하니 에러가 발생함.
    * **해결:** int() 함수를 사용해 입력값을 숫자로 바꿔주는 '형변환' 과정을 거친 뒤에 트렌드 지수를 계산하도록 고침.
2. **문제 2: 조건문 뒤에 자꾸 생기는 빨간 줄 (SyntaxError)**
    * **원인:**코디 등급을 나누기 위해 if와 elif 조건식을 쓰면서, 문장 끝에 꼭 들어가야 하는 마법의 기호인 콜론(:)을 자꾸 빠뜨려서 문법 에러가 남.
    * **해결:** 파이썬의 모든 조건문 끝에는 항상 땡땡(:)이 들어가야 한다는 규칙을 확실히 머릿속에 넣고 코드를 전부 수정함.

## 🟨 [3차 과제: V3.0] 무한 루프와 메뉴 시스템 (반복문) - 향후 작성 예정
## 🟨 [3차 과제: V3.0] 무한 루프와 메뉴 시스템 (반복문)
### ✨3차 과제 업데이트 내용:
* 무한 루프(while True) 적용: 저번 과제에서는 메뉴를 한 번 고르면 프로그램이 바로 꺼져서 아쉬웠는데, 이번에는 while True를 써서 직접 3번(종료)을 누르기 전까지는 계속 메뉴판이 뜨도록 수정했습니다.
* 메뉴 선택 기능 만들기: input()으로 번호를 입력받고, if-elif-else문을 써서 1번(옷 추가), 2번(옷장 확인), 3번(종료) 기능이 각각 실행되도록 분리했습니다.
* 잘못된 번호 방지(continue): 1, 2, 3번 말고 메뉴에 없는 번호를 누르면 프로그램이 에러가 나는 문제가 있었습니다. 그래서 else문이랑 continue를 써서 "잘못된 입력입니다"라고 알려주고, 프로그램이 꺼지는 대신 다시 처음 메뉴판으로 돌아가게 안전장치를 달았습니다.
* 깔끔한 종료(break): 3번을 누르면 인사말이 나오고 break로 무한 루프를 빠져나가면서 프로그램이 정상적으로 꺼지도록 만들었습니다.
* 데이터 초기화 에러 해결: 처음엔 while문 안에 옷장 리스트를 만들었더니 메뉴가 한 바퀴 돌 때마다 데이터가 다 리셋돼서 날아가는 현상이 있었습니다. 그래서 closet = [] 위치를 반복문 바깥(맨 위)으로 빼서 옷 데이터가 차곡차곡 쌓이게 고쳤습니다.
### **🤖 AI 파트너십 과정**
### **🤖 AI 파트너십 과정**
 1. **데이터 초기화 에러 해결**
    * **프롬프트 요약:** while True로 루프를 돌릴 때마다 기껏 추가한 옷 데이터가 자꾸 날아가는 이유와 해결 방법을 질문함.
    * **적용 내용:** 리스트를 만드는 위치가 문제라는 피드백을 받고, `closet = []` 코드를 while문 바깥(맨 위)으로 빼서 데이터가 안전하게 누적되도록 구조를 수정함.

 2. **조건문 자료형 인식 오류 수정**
    * **프롬프트 요약:** input()으로 분명히 1을 입력했는데도 if문 안으로 안 들어가고 자꾸 '잘못된 입력'으로 빠지는 원인을 질문함.
    * **적용 내용:** 파이썬은 input() 값을 무조건 문자열(글자)로 인식한다는 점을 새롭게 배웠고, `if menu == 1:`을 `if menu == '1':`처럼 문자열 비교로 바꿔서 오류를 고침.

 3. **continue를 활용한 예외 처리 도입**
    * **프롬프트 요약:** 메뉴판에 없는 4번 같은 이상한 번호를 눌렀을 때, 프로그램이 그냥 꺼지지 않고 다시 처음 메뉴로 돌아가게 하는 코드를 물어봄.
    * **적용 내용:** 조건문 맨 마지막 else 부분에 경고 메시지를 넣고 `continue`를 추가해서, 에러가 나도 프로그램이 튕기지 않고 메인 메뉴판으로 돌아가도록 안정성을 높임.
    
### **🛠️ Troubleshooting & 기술 회고:**
 ### **🛠️ Troubleshooting & 기술 회고:**
  1. **문제 1:** 옷을 추가해도 다음 메뉴로 넘어가면 저장된 옷 데이터가 전부 날아가는 현상
     * **원인:** 옷 데이터를 담을 closet = [] 리스트를 while True 반복문 안쪽에 적어둬서, 메뉴가 한 바퀴 돌 때마다 빈 리스트로 계속 덮어씌워졌음.
     * **해결:** closet = [] 코드를 while문 밖(맨 위)으로 꺼내서 반복문이 돌아도 옷장이 초기화되지 않게 고침.

  2. **문제 2:** 1번을 입력해도 자꾸 잘못된 입력이라고 뜨면서 옷 추가 기능으로 안 넘어가는 문제
     * **원인:** input()으로 받은 값은 파이썬이 무조건 글자(문자열)로 인식하는데, 조건문에서는 if menu == 1: 처럼 진짜 숫자 1이랑 비교하려고 해서 두 개가 다르다고 판단한 거였음.
     * **해결:** if menu == '1': 처럼 숫자 양옆에 따옴표를 붙여서 글자끼리 비교하게 만들어서 오류를 해결함.

  3. **문제 3:** 메뉴에 없는 이상한 번호를 누르면 프로그램이 아무 반응 없이 그냥 종료돼버림
     * **원인:** 1, 2, 3번 말고 다른 번호가 들어왔을 때 어떻게 하라는 명령(else)이 없어서 코드가 더 이상 실행될 게 없어 끝나버린 거임.
     * **해결:** 마지막에 else문을 추가해서 경고 메시지를 띄우게 하고, continue를 써서 프로그램이 튕기지 않고 다시 첫 메뉴판으로 돌아가게 안전장치를 만듦.

### 🟥 [4차 과제: V4.0] 모듈화 및 데이터 확장 (배열과 함수) - 🌟최종 완성 -- 향후 작성 예정
### **✨4차 과제 업데이트 내용:**
함수(def) 도입: 코드가 길어지고 복잡해져서 옷 추가하기, 옷장 확인하기 등의 주요 기능들을 각각 독립된 함수로 분리했습니다.

딕셔너리(Dictionary) 전환: 기존에는 리스트 안에 리스트를 넣어서 인덱스 번호(0, 1, 2)로만 데이터를 찾았는데, 이제는 딕셔너리를 도입해 '이름', '가격' 같은 명확한 키워드로 데이터를 훨씬 알아보기 쉽게 관리하도록 업그레이드했습니다.

모듈화(import) 적용: 기능별 함수들을 메인 코드에 다 몰아넣지 않고, 별도의 파이썬 파일로 깔끔하게 떼어낸 뒤 메인 파일에서 import로 불러와서 실행하도록 전체적인 파일 구조를 전문가처럼 다듬었습니다.
    
### **🤖 AI 파트너십 과정**
1.딕셔너리 데이터 구조 변환

프롬프트 요약: 2차원 리스트로 저장하던 옷 데이터를 딕셔너리 형태로 바꾸려면 append 코드를 어떻게 수정해야 하는지 질문함.

적용 내용: append() 괄호 안에 중괄호 {}를 써서 키(key)와 값(value)을 한 쌍으로 묶어 리스트에 추가하는 방법을 새롭게 배우고 프로그램에 적용함.

2.함수 분리와 매개변수 활용

프롬프트 요약: 옷 추가 기능을 함수로 따로 뺐더니, 메인에 있던 옷장 리스트를 함수 안에서 인식하지 못하는 에러의 해결법을 질문함.

적용 내용: 함수 바깥에 있는 데이터를 함수 안에서 쓰려면 괄호 안에 매개변수로 넘겨줘야 한다는 점을 피드백받고, 코드 구조를 자연스럽게 수정함.
    
### **🛠️ Troubleshooting & 기술 회고:**
문제 1: 함수로 분리한 뒤에 옷을 추가해도 메인 메뉴에서 옷장이 비어있다고 나오는 현상

원인: 함수 안에서 새롭게 저장한 데이터가 함수 종료와 함께 날아가 버리고, 메인에 있는 진짜 옷장 리스트에는 반영이 안 돼서 발생한 문제였음.

해결: 함수에서 옷을 추가한 뒤에 return을 써서 결과값을 메인으로 돌려주거나, 처음부터 리스트 자체를 매개변수로 넘겨받아 직접 추가하게 만들어서 데이터 유실을 막음.

문제 2: 모듈화(import)를 했는데 '정의되지 않은 함수'라고 에러가 뜨는 현상

원인: 기능들을 모아둔 외부 파일 이름이랑 import 할 때 적은 이름이 다르거나, 메인 파일에서 함수 이름 스펠링을 잘못 적어서 컴퓨터가 파일을 못 찾는 거였음.

해결: 파일명과 import 문법을 똑같이 맞추고, '모듈명.함수명()' 형태로 정확하게 호출하도록 수정해서 에러를 완벽하게 잡음.
